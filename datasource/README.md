## 换乘站展示位置

仅合并同名且组内两两原始距离小于 1 km 的跨线路站点。不同名字的换乘站保持各自名称和位置，例如杭州火车东站与火车东站（东广场）。各线路的站点 ID 和记录仍分别保留，正式数据中的原始坐标及轨迹不变。

比较原始站点附近轨迹的局部方向；原始方向和相交线段的夹角均大于 20° 时，才考虑附近交点。平行、锐角、方向不稳定或交点不合理时，两位置取中点，多位置取中心。最终每个站点的移动必须同时不超过 200 米和组内最大原始间距的三倍；必要时选取最小最大距离中心，无法满足则保留各自原始位置。组内跨度超过 400 米直接保留原位置。三倍间距比较允许 0.01 米的浮点误差。

本次共检查 1,322 个候选组：1,308 组合并，14 组保留原位置；286 组采用交点，1,022 组采用中心（其中天津西站采用优化中心）。32 组因交点超限回退到中心。全部站点最大移动约 199.1 米，超出上述限制的组为零。

蓝村路、清河站等近似平行线路使用中心，避免偶然交点造成漂移。旧新坐标差距较大的五站抽样中，四站支持新坐标；上海 1 号线徐家汇与独立参考点仍有约 172 米差距，保留精度疑点。展示坐标用于统一站点绘制，不代表测绘确认的站台中心。

同时修正轨迹图层重复绘制整条线路，以及跨城相同线路 ID 的图层覆盖问题。

## 更新与验证

根目录 `.env.local` 配置 `AMAP_WEB_SERVICE_KEY`，使用高德 Web 服务 Key；Key 仅供本地采集，不写入前端或 Git。权限、额度和速率限制以高德账号控制台为准。

```sh
pnpm data:update fetch       # 下载目录与真实轨迹，不修改正式数据
pnpm data:update geometry    # 下载中断后，沿用当前目录继续获取轨迹
pnpm data:update verify      # 校验并暂存；存在缺失线路时返回非零状态
pnpm data:update apply --omit-line=7101:900000192971
pnpm data:update audit      # 检查全量换乘点偏移，超限时返回非零状态
pnpm test
pnpm typecheck
pnpm build
```

更新入口不带参数时显示帮助，只有显式执行 `apply` 才覆盖正式数据。默认拒绝未解决线路；`--omit-line=城市ID:线路ID` 仅用于明确接受的缺失项，上面的参数对应本次台北淡水信义线，后续更新应重新核验。不同的缺失线路可以分别传入多个参数。

轨迹缓存必须不早于当前目录采集时间，旧缓存会重新获取，验证和应用均拒绝旧缓存或无效时间戳。应用前备份旧数据，并检查暂存期间正式数据没有变化；正式数据使用两空格缩进。

正式数据为 `data.json`，来源记录为 `metadata.json`。原始响应、候选数据、过程报告和旧数据备份均在 Git 忽略的 `.data-cache/amap/`：验证报告为 `geometry-report.json`，换乘审计为 `transfer-audit.json`，备份位于 `backups/`。采集工具按来源下载、轨迹下载、数据校验及换乘审计拆分，统一通过 `data:update` 调用。
